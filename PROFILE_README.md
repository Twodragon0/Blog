# Superseded — the profile README lives in its own repository

The GitHub profile README is now maintained at **[`Twodragon0/Twodragon0`](https://github.com/Twodragon0/Twodragon0)**,
which pulls the blog feeds itself. Edit it there.

## Why this file no longer holds the content

This file used to be generated by `profile_readme_generator.py`, and the workflow that ran
it ended by printing *"Create a repository named 'Twodragon0' … copy the content to that
repository's README.md"*. That copy step was manual and never happened, so the generated
output sat here and drifted:

- it pinned `Twodragon0/AWS`, a repository that has since been renamed to
  [`aws-devsecops-infrastructure`](https://github.com/Twodragon0/aws-devsecops-infrastructure)
  — the pin card rendered an error;
- it listed `2twodragon.com` as a post source, which serves no feed (verified 2026-09-11:
  `/rss`, `/feed` and `/feed/` all return HTTP 200 with zero `<item>` elements);
- it duplicated the same blog-post section this repository's own `README.md` already has.

Two places generating the same artifact, with only one of them reachable, is how the drift
started. The profile repository now owns it, so the scheduled generator here was removed
(`.github/workflows/update-profile.yml`). `profile_readme_generator.py` is kept for
reference but is no longer wired to anything.
